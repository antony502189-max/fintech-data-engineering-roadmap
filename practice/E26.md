# E26. Full reconciliation

**Module:** Financial data and money movement. **Time:** 30–90 minutes. **Prerequisites:** [related lesson](../roadmap/07-fintech/063-reconciliation.md).

## Task

Compare expected and actual mappings by payment:currency. For the union of keys, return matched, amount_mismatch, missing_external, or unexpected_external.

Contract: `solve(data) -> JSON-compatible result`. All inputs are synthetic; do not mutate the input. Use Python's standard library. Handle invalid inputs only as explicitly required by this task.

## Get started

1. From the repository root, run `python practice/run.py init E26`. It creates your personal copy at `work/answers/E26.py` without overwriting an existing file.
2. Open the file and replace `NotImplementedError` with your implementation.
3. Run `python practice/run.py grade E26`. Before implementation, this command must fail.
4. Add your own boundary case in a separate test: the provided cases cover a minimum, not every possible defect.
5. Save your solution, verification result, and two sentences explaining the business impact of the mistake in your fork.

## Example input and expected result

```json
{
  "input": {
    "expected": {
      "p1:USD": 100,
      "p2:EUR": 50
    },
    "actual": {
      "p1:USD": 99,
      "p3:USD": 20
    }
  },
  "expected": {
    "p1:USD": "amount_mismatch",
    "p2:EUR": "missing_external",
    "p3:USD": "unexpected_external"
  }
}
```

Other verification cases are in [cases.json](cases.json). Implement the rule rather than hardcoding fixture answers; check it on your own example.

## Hint

Preserve records absent on either side.
