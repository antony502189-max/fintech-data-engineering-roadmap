# E26. Полная сверка

**Модуль:** Финтех и движение денег. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/07-fintech/063-reconciliation.md).

## Условие

Сверь expected и actual mappings по ключу payment:currency. Для union keys верни matched, amount_mismatch, missing_external или unexpected_external.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E26`. Это создаст личную копию `work/answers/E26.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E26`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "expected": {
      "p1:USD": 100,
      "p2:EUR": 50
    },
    "actual": {
      "p1:USD": 99,
      "p3:USD": 20
    }
  },
  "expected": {
    "p1:USD": "amount_mismatch",
    "p2:EUR": "missing_external",
    "p3:USD": "unexpected_external"
  }
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.
