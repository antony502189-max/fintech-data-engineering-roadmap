# E36. Retention и hold

**Модуль:** Платформа и безопасность. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/09-platform/085-retention.md).

## Условие

По заданной synthetic policy выбери IDs для удаления: expiry<=today и hold=false. Даты ISO; верни sorted list. Это реализация входной политики, не выбор законного срока.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E36`. Это создаст личную копию `work/answers/E36.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E36`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "today": "2026-02-01",
    "records": [
      {
        "id": "a",
        "expiry": "2026-01-01",
        "hold": true
      },
      {
        "id": "b",
        "expiry": "2026-02-01",
        "hold": false
      },
      {
        "id": "c",
        "expiry": "2026-03-01",
        "hold": false
      }
    ]
  },
  "expected": [
    "b"
  ]
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.

## Подсказка

Hold имеет приоритет над expiry.
