# E22. Retry policy

**Модуль:** Трансформации и оркестрация. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/06-transformation/054-retry-design.md).

## Условие

Классифицируй ошибки: rate_limit и timeout→retry; schema→quarantine; conflict и все неизвестные→fail.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E22`. Это создаст личную копию `work/answers/E22.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E22`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": [
    "rate_limit",
    "schema",
    "conflict",
    "unknown"
  ],
  "expected": [
    "retry",
    "quarantine",
    "fail",
    "fail"
  ]
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.

## Подсказка

Контрактный дефект не лечится ожиданием.
