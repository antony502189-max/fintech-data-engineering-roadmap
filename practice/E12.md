# E12. Бизнес-время и время знания

**Модуль:** Моделирование DWH. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/03-modeling/026-bitemporal.md).

## Условие

Выбери rate из записей с effective<=business_at и recorded<=known_at. Среди допустимых предпочитай latest effective, затем latest recorded. Верни null при отсутствии.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E12`. Это создаст личную копию `work/answers/E12.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E12`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "business_at": "2026-01-31",
    "known_at": "2026-01-31",
    "versions": [
      {
        "effective": "2026-01-01",
        "recorded": "2026-01-01",
        "rate": 1
      },
      {
        "effective": "2026-01-01",
        "recorded": "2026-02-05",
        "rate": 2
      }
    ]
  },
  "expected": 1
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.
