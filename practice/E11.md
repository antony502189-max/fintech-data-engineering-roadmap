# E11. Unknown dimension member

**Module:** DWH modeling. **Time:** 30–90 minutes. **Prerequisites:** [related lesson](../roadmap/03-modeling/024-dimensions.md).

## Task

Join every fact to a merchant name, using UNKNOWN for missing merchants. Preserve input order and every amount.

Contract: `solve(data) -> JSON-compatible result`. All inputs are synthetic; do not mutate the input. Use Python's standard library. Handle invalid inputs only as explicitly required by this task.

## Get started

1. From the repository root, run `python practice/run.py init E11`. It creates your personal copy at `work/answers/E11.py` without overwriting an existing file.
2. Open the file and replace `NotImplementedError` with your implementation.
3. Run `python practice/run.py grade E11`. Before implementation, this command must fail.
4. Add your own boundary case in a separate test: the provided cases cover a minimum, not every possible defect.
5. Save your solution, verification result, and two sentences explaining the business impact of the mistake in your fork.

## Example input and expected result

```json
{
  "input": {
    "facts": [
      {
        "payment": "p1",
        "merchant": "m1",
        "amount": 100
      },
      {
        "payment": "p2",
        "merchant": "m9",
        "amount": 100
      }
    ],
    "merchants": {
      "m1": "Shop"
    }
  },
  "expected": [
    {
      "payment": "p1",
      "name": "Shop",
      "amount": 100
    },
    {
      "payment": "p2",
      "name": "UNKNOWN",
      "amount": 100
    }
  ]
}
```

Other verification cases are in [cases.json](cases.json). Implement the rule rather than hardcoding fixture answers; check it on your own example.

## Hint

Use LEFT JOIN semantics; dimensions must not filter money away.
