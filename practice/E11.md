# E11. Unknown dimension

**Модуль:** Моделирование DWH. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/03-modeling/024-dimensions.md).

## Условие

Соедини каждый факт с merchant name, неизвестных пометь UNKNOWN. Верни строки в исходном порядке и сохрани все amount.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E11`. Это создаст личную копию `work/answers/E11.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E11`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "facts": [
      {
        "payment": "p1",
        "merchant": "m1",
        "amount": 100
      },
      {
        "payment": "p2",
        "merchant": "m9",
        "amount": 100
      }
    ],
    "merchants": {
      "m1": "Shop"
    }
  },
  "expected": [
    {
      "payment": "p1",
      "name": "Shop",
      "amount": 100
    },
    {
      "payment": "p2",
      "name": "UNKNOWN",
      "amount": 100
    }
  ]
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.

## Подсказка

LEFT JOIN semantics; dimension не должен фильтровать деньги.
