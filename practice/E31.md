# E31. Checks при неполном входе

**Модуль:** Качество и эксплуатация. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/08-reliability/071-quality-dimensions.md).

## Условие

Верни quality flags complete и amounts_match по mappings. amounts_match требует полного совпадения keys и amounts; одинаковый count не достаточен.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E31`. Это создаст личную копию `work/answers/E31.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E31`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "expected": {
      "a": 100,
      "b": 200
    },
    "actual": {
      "a": 100,
      "c": 200
    }
  },
  "expected": {
    "complete": false,
    "amounts_match": false
  }
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.

## Подсказка

Независимый expected set обязателен.
