# E37. Point-in-time feature

**Модуль:** ИИ, ML и портфолио. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/10-ai-career/096-feature-store.md).

## Условие

Сложи capture amounts для payment и currency, когда event_time<decision_at и received_at<=decision_at. Fixture timestamps — нормализованный UTC ISO.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E37`. Это создаст личную копию `work/answers/E37.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E37`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "payment": "p",
    "currency": "USD",
    "decision_at": "2026-01-02",
    "events": [
      {
        "payment": "p",
        "currency": "USD",
        "amount": 100,
        "event_time": "2026-01-01",
        "received_at": "2026-01-03"
      }
    ]
  },
  "expected": 0
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.
