# E37. Point-in-time feature

**Module:** AI, ML and portfolio. **Time:** 30–90 minutes. **Prerequisites:** [related lesson](../roadmap/10-ai-career/096-feature-store.md).

## Task

Sum capture amounts for payment and currency where event_time<decision_at and received_at<=decision_at. Fixture timestamps are normalized UTC ISO.

Contract: `solve(data) -> JSON-compatible result`. All inputs are synthetic; do not mutate the input. Use Python's standard library. Handle invalid inputs only as explicitly required by this task.

## Get started

1. From the repository root, run `python practice/run.py init E37`. It creates your personal copy at `work/answers/E37.py` without overwriting an existing file.
2. Open the file and replace `NotImplementedError` with your implementation.
3. Run `python practice/run.py grade E37`. Before implementation, this command must fail.
4. Add your own boundary case in a separate test: the provided cases cover a minimum, not every possible defect.
5. Save your solution, verification result, and two sentences explaining the business impact of the mistake in your fork.

## Example input and expected result

```json
{
  "input": {
    "payment": "p",
    "currency": "USD",
    "decision_at": "2026-01-02",
    "events": [
      {
        "payment": "p",
        "currency": "USD",
        "amount": 100,
        "event_time": "2026-01-01",
        "received_at": "2026-01-03"
      }
    ]
  },
  "expected": 0
}
```

Other verification cases are in [cases.json](cases.json). Implement the rule rather than hardcoding fixture answers; check it on your own example.
