# E23. Affected incremental days

**Module:** Transformations and orchestration. **Time:** 30–90 minutes. **Prerequisites:** [related lesson](../roadmap/06-transformation/052-dbt-incremental.md).

## Task

Return sorted unique event_day values for records with received_seq>checkpoint. Receipt progress selects arrivals; business dates select partitions to rebuild.

Contract: `solve(data) -> JSON-compatible result`. All inputs are synthetic; do not mutate the input. Use Python's standard library. Handle invalid inputs only as explicitly required by this task.

## Get started

1. From the repository root, run `python practice/run.py init E23`. It creates your personal copy at `work/answers/E23.py` without overwriting an existing file.
2. Open the file and replace `NotImplementedError` with your implementation.
3. Run `python practice/run.py grade E23`. Before implementation, this command must fail.
4. Add your own boundary case in a separate test: the provided cases cover a minimum, not every possible defect.
5. Save your solution, verification result, and two sentences explaining the business impact of the mistake in your fork.

## Example input and expected result

```json
{
  "input": {
    "checkpoint": 5,
    "events": [
      {
        "received_seq": 6,
        "event_day": "2026-01-01"
      },
      {
        "received_seq": 5,
        "event_day": "2026-01-03"
      }
    ]
  },
  "expected": [
    "2026-01-01"
  ]
}
```

Other verification cases are in [cases.json](cases.json). Implement the rule rather than hardcoding fixture answers; check it on your own example.

## Hint

A late event can change an old partition.
