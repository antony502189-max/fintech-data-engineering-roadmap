# E23. Затронутые дни incremental

**Модуль:** Трансформации и оркестрация. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/06-transformation/052-dbt-incremental.md).

## Условие

Для received_seq>checkpoint верни отсортированные уникальные event_day. Checkpoint хранит delivery progress, итог пересчитывается по business day.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E23`. Это создаст личную копию `work/answers/E23.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E23`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "checkpoint": 5,
    "events": [
      {
        "received_seq": 6,
        "event_day": "2026-01-01"
      },
      {
        "received_seq": 5,
        "event_day": "2026-01-03"
      }
    ]
  },
  "expected": [
    "2026-01-01"
  ]
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.

Позднее событие меняет старую partition.
