# E24. Publication gate

**Module:** Transformations and orchestration. **Time:** 30–90 minutes. **Prerequisites:** [related lesson](../roadmap/06-transformation/056-publish.md).

## Task

Publish candidate only when complete=true, checks_pass=true, and critical_exceptions=0. Otherwise return previous version.

Contract: `solve(data) -> JSON-compatible result`. All inputs are synthetic; do not mutate the input. Use Python's standard library. Handle invalid inputs only as explicitly required by this task.

## Get started

1. From the repository root, run `python practice/run.py init E24`. It creates your personal copy at `work/answers/E24.py` without overwriting an existing file.
2. Open the file and replace `NotImplementedError` with your implementation.
3. Run `python practice/run.py grade E24`. Before implementation, this command must fail.
4. Add your own boundary case in a separate test: the provided cases cover a minimum, not every possible defect.
5. Save your solution, verification result, and two sentences explaining the business impact of the mistake in your fork.

## Example input and expected result

```json
{
  "input": {
    "complete": true,
    "checks_pass": true,
    "critical_exceptions": 0,
    "candidate": "v2",
    "previous": "v1"
  },
  "expected": "v2"
}
```

Other verification cases are in [cases.json](cases.json). Implement the rule rather than hardcoding fixture answers; check it on your own example.

## Hint

Do not switch a pointer after partially successful checks.
