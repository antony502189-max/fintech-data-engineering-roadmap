# E34. Personal-data allowlist

**Module:** Platform and security. **Time:** 30–90 minutes. **Prerequisites:** [related lesson](../roadmap/09-platform/082-pii.md).

## Task

Return only payment_id, currency, and amount_minor from the synthetic payload. Unknown fields must not appear in output.

Contract: `solve(data) -> JSON-compatible result`. All inputs are synthetic; do not mutate the input. Use Python's standard library. Handle invalid inputs only as explicitly required by this task.

## Get started

1. From the repository root, run `python practice/run.py init E34`. It creates your personal copy at `work/answers/E34.py` without overwriting an existing file.
2. Open the file and replace `NotImplementedError` with your implementation.
3. Run `python practice/run.py grade E34`. Before implementation, this command must fail.
4. Add your own boundary case in a separate test: the provided cases cover a minimum, not every possible defect.
5. Save your solution, verification result, and two sentences explaining the business impact of the mistake in your fork.

## Example input and expected result

```json
{
  "input": {
    "payment_id": "p",
    "currency": "USD",
    "amount_minor": 100,
    "name": "SYNTHETIC",
    "new_sensitive_field": "SYNTHETIC"
  },
  "expected": {
    "payment_id": "p",
    "currency": "USD",
    "amount_minor": 100
  }
}
```

Other verification cases are in [cases.json](cases.json). Implement the rule rather than hardcoding fixture answers; check it on your own example.

## Hint

Allowlists handle new sensitive fields better than blacklists.
