# E34. PII allowlist projection

**Модуль:** Платформа и безопасность. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/09-platform/082-pii.md).

## Условие

Верни только разрешённые поля payment_id, currency, amount_minor из synthetic payload. Неизвестные поля не должны просочиться.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E34`. Это создаст личную копию `work/answers/E34.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E34`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "payment_id": "p",
    "currency": "USD",
    "amount_minor": 100,
    "name": "SYNTHETIC",
    "new_sensitive_field": "SYNTHETIC"
  },
  "expected": {
    "payment_id": "p",
    "currency": "USD",
    "amount_minor": 100
  }
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.

## Подсказка

Allowlist защищает от новых sensitive keys лучше blacklist.
