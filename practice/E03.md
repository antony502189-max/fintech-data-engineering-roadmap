# E03. Контракт на границе

**Модуль:** Инженерная база. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/01-foundations/003-python.md).

## Условие

Проверь strict event contract. Верни accepted или rejected; bool не должен считаться integer amount.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E03`. Это создаст личную копию `work/answers/E03.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E03`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "event_id": "e",
    "payment_id": "p",
    "kind": "captured",
    "amount_minor": 100,
    "currency": "USD",
    "event_time": "2026-01-01T12:00:00+00:00",
    "received_at": "2026-01-01T12:00:00+00:00"
  },
  "expected": "accepted"
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.

## Подсказка

Используй type(value) is int, а не только isinstance.
