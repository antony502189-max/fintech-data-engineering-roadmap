# E17. Partition pruning

**Модуль:** Хранилища и вычисления. **Время:** 30–90 минут. **Prerequisites:** [связанный урок](../roadmap/05-storage/042-partitioning.md).

## Условие

Сложи bytes только partitions в интервале start<=day<end. Это offline расчёт pruning, а не benchmark движка.

Контракт `solve(data) -> JSON-compatible result`. Все входы синтетические; функция не должна менять вход. Для этого упражнения используй стандартную библиотеку Python. Несогласованные входы обрабатывай только так, как явно требует условие.

## Как начать

1. Из корня репозитория выполни `python practice/run.py init E17`. Это создаст личную копию `work/answers/E17.py` без перезаписи существующей.
2. Открой файл и замени `NotImplementedError` своей реализацией.
3. Выполни `python practice/run.py grade E17`. До реализации команда обязана завершаться ошибкой.
4. Добавь свой граничный пример в отдельный тест: fixture cases проверяют минимум, а не все возможные ошибки.
5. Сохрани решение, результат проверки и два предложения о бизнес-последствии ошибки в своём форке.

## Пример входа и ожидаемого результата

```json
{
  "input": {
    "start": "2026-01-01",
    "end": "2026-01-03",
    "partitions": [
      {
        "day": "2026-01-01",
        "bytes": 100
      },
      {
        "day": "2026-01-02",
        "bytes": 200
      },
      {
        "day": "2026-01-03",
        "bytes": 300
      }
    ]
  },
  "expected": 300
}
```

Остальные проверочные cases находятся в [cases.json](cases.json). Не подставляй ответы из fixtures: проверяй правило на собственном примере.

## Подсказка

Полуоткрытый интервал; исключи partition на end.
