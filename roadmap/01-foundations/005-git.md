# 005. Git, ревью и воспроизводимость

## Результат обучения

Сделать изменение модели понятным для независимого ревьюера.

## Как это работает

Коммит связывает конкретный снимок кода с объяснением изменения. Маленький содержательный diff легче проверить, но число коммитов не измеряет зрелость системы. Версия кода недостаточна для воспроизведения: нужны версия входа, параметры запуска и окружение. Даты нельзя подменять ради видимости многолетней разработки.

## Пример из финтеха

Исправление фильтра возвратов меняет итог за прошлый месяц. Ревью должно увидеть бизнес-эффект, тест и план пересчёта.

## Порядок реализации

1. Создай ветку в своём форке
2. Добавь минимальное изменение
3. Покажи before-after на фикстуре
4. Опиши scope пересчёта в PR.

## Практическое задание

Исправь намеренно ошибочную формулу net в копии SQL; приложи один тест, доказывающий ошибку, и описание изменившихся итогов.

## Типичная ошибка и её последствия

Большой коммит смешивает переименование, новую формулу и миграцию. Проверить денежное изменение становится трудно.
