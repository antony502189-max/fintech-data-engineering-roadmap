# 082. Personal-data minimization and tokenization

## Learning outcome

Reduce sensitive analytical data to what is necessary.

## How it works

Start with purpose: retain a field only for a defined task. Tokens replace identifiers but may still allow linkage or reidentification. Hashing alone does not establish anonymity. Financial aggregates generally need neither full card numbers nor document scans.

## Fintech example

Payment and provider references support reconciliation; a customer name rarely helps compare amounts.

## Implementation steps

1. Classify fields
2. Define an analytical projection
3. Separate token mappings
4. Inspect logs and exports.

## Practical assignment

Implement an allowlist projection over synthetic payloads that excludes unknown fields.

## Common mistake and its consequences

A blacklist removes known sensitive fields while newly introduced passport_scan passes through.

## Verify the result

Only approved fields enter output, including when unexpected sensitive fields are added.

## Self-check question

When can combinations of apparently harmless fields enable reidentification?
