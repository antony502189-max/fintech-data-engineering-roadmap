# 086. Infrastructure as Code and safe changes

## Learning outcome

Make configuration reproducible and reviewable.

## How it works

IaC describes resources; a plan presents proposed changes. State can contain sensitive information and needs protection. Provider and module versions affect reproducibility. Applying changes may replace or delete resources, so teaching exercises separate reviewed plans from infrastructure mutation.

## Fintech example

A changed storage name causes replacement and threatens retained data.

## Implementation steps

1. Describe resources
2. Pin versions
3. Inspect the plan
4. Define backup and recovery limits.

## Practical assignment

Create a design-only Terraform skeleton without credentials and identify destructive actions.

## Common mistake and its consequences

Committing state publicly exposes information; reverting configuration cannot restore a deleted bucket's data.

## Verify the result

Distinguish configuration rollback from data restoration and exclude state from Git.

## Self-check question

Why does yesterday's plan not guarantee today's apply behavior?
