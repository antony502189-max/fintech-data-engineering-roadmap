# 086. Infrastructure as Code и безопасное изменение

## Результат обучения

Сделать платформенную конфигурацию воспроизводимой и обозримой.

## Как это работает

IaC описывает желаемые resources; plan показывает предполагаемый diff. State содержит чувствительные сведения и требует защиты. Provider version и module version влияют на воспроизводимость. Apply может изменить или удалить ресурсы, поэтому учебный проект должен отделять review plan от реального изменения инфраструктуры.

## Пример из финтеха

Неверное имя storage resource вызывает replacement и риск потери данных.

## Порядок реализации

1. Опиши resources
2. Зафиксируй versions
3. Проверь plan
4. Определи backup и rollback limitations.

## Практическое задание

Создай design-only Terraform skeleton без credentials; перечисли, какие actions потенциально destructive.

## Типичная ошибка и её последствия

State коммитят в публичный GitHub; «revert config» считают восстановлением удалённого bucket.

## Проверка результата

Документ различает configuration rollback и data recovery, state исключён из Git.

## Вопрос для самопроверки

Почему plan, созданный вчера, нельзя считать гарантией сегодняшнего apply?
