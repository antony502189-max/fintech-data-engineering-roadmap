# 056. Атомарная публикация и ready-marker

## Результат обучения

Не дать потребителю увидеть половину итогового набора.

## Как это работает

Compute и publish — разные стадии. Candidate dataset строится отдельно, проходит checks и затем становится видимым через атомарный pointer, view switch или поддерживаемый table commit. Ready marker содержит версию и scope. Механизм переключения зависит от платформы и её гарантий.

## Пример из финтеха

USD partition готова, EUR ещё строится; отчёт за день не должен выглядеть окончательно завершённым.

## Порядок реализации

1. Создай candidate version
2. Выполни quality и reconciliation
3. Опубликуй указатель
4. Сохрани previous version.

## Практическое задание

Разработай manifest для daily cash с обеими валютами и одним published version.

## Типичная ошибка и её последствия

Пишут directly в открытую consumer table и обновляют строки по одной.

## Проверка результата

Consumer читает либо old complete, либо new complete; partial state отсутствует в сценарии сбоя.

## Вопрос для самопроверки

Как обеспечить согласованную публикацию нескольких взаимозависимых marts?
