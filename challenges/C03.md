# C03. Grouped payouts and independent reconciliation

**Level:** intermediate to advanced. **Time:** 2–5 hours. [Related material 1](../roadmap/07-fintech/063-reconciliation.md) · [Related material 2](../docs/MONEY_CORRECTNESS.md)

## Scenario and contract

Inputs contain normalized payment `ledger`, explicit payment-to-payout `membership`, and independent payout `statements`. Payment identity is provider,payment,currency; payout identity is provider,payout,currency. Amounts are signed integer minor units.

Aggregate only explicitly allocated ledger records into expected payouts. Return `payouts` sorted by payout identity with expected_minor, actual_minor, delta_minor=actual−expected, and status matched/amount_mismatch/missing_external/unexpected_external. Missing sides use null, not zero. Return sorted `unallocated` payment-key arrays.

Validate in order: duplicate ledger keys → duplicate_ledger; duplicate payment allocation → duplicate_allocation; unknown membership payment → unknown_payment; duplicate statement keys → duplicate_statement. On these defects return only {"error":reason}. This exercise assumes whole-payment allocation, not partial allocation or fuzzy amount matching.

## Hint

Provider namespaces and currency are part of identity. Zero is a valid confirmed amount; absence is not zero.

## Deliverables and review

A payout reconciliation report with an unallocated-payment exception queue.

Keep the implementation, passing output, one failing counterexample, and a short note explaining the financial or operational consequence. Check the input contract rather than silently extending it. Synthetic fixtures do not establish production-scale or regulatory guarantees.
