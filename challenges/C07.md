# C07. Debug a plausible but wrong SQL report

**Level:** intermediate to advanced. **Time:** 2–5 hours. [Related material 1](../roadmap/02-sql/012-joins.md) · [Related material 2](../docs/SQL_PATTERNS.md)

## Scenario and contract

The starter executes a query and returns plausible output, but contains real financial fanout defects. Repair it rather than replacing expected fixture values.

Inputs are captures [event_id,payment,currency,amount], fees with the same structure, and attempts [attempt_id,payment]. Source IDs are unique; multiple distinct equal-value events are valid. Return one row per payment/currency with at least one capture: [payment,currency,gross_minor,net_minor,attempt_count], sorted by payment,currency. Net is capture minus fees; attempts count at payment grain across currencies. Preserve captures with no fees or attempts. Fee-only records are outside this query's stated population.

Use actual SQLite SQL and explain why SUM(DISTINCT amount) is not deduplication. Pre-aggregate independent inputs before joining.
