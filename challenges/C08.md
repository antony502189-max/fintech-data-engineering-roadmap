# C08. Leakage-safe training data with delayed labels

**Level:** intermediate to advanced. **Time:** 2–5 hours. [Related material 1](../roadmap/07-fintech/068-fraud-data.md) · [Related material 2](../roadmap/10-ai-career/097-ml-pipelines.md)

## Scenario and contract

Build training rows for supplied decisions. Enforce label maturity and source knowledge before creating features. Decisions are sorted by ID in output; label IDs are unique. Exclusion priority: decision_at+maturity_days>training_as_of → immature; no label → missing_label; label known_at>training_as_of → label_not_yet_known.

For included decisions, sum captured events for the same entity and currency within [decision_at-window_seconds,decision_at), received no later than decision_at. Normalize timestamp offsets. Return id,split,label,capture_minor, and sorted contributing event_ids. Split: decision_at<train_end means train; otherwise before validation_end means validation; otherwise test. Return {included:[...],excluded:[{id,reason}]}.

This builds a reproducible dataset, not a classifier or real feature store.

## Hint

A historically early event received later is unavailable. Keep feature windows and label maturity as separate constraints.

## Deliverables and review

A training manifest, row-level event provenance, and negative examples showing leakage and label exclusion.

Keep the implementation, passing output, one failing counterexample, and a short note explaining the financial or operational consequence. Check the input contract rather than silently extending it. Synthetic fixtures do not establish production-scale or regulatory guarantees.
