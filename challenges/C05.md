# C05. Original and restated bitemporal reports

**Level:** intermediate to advanced. **Time:** 2–5 hours. [Related material 1](../roadmap/03-modeling/026-bitemporal.md) · [Related material 2](../docs/SQL_PATTERNS.md)

## Scenario and contract

Store supplied `records` as a SQLite history with both valid and recorded intervals. Query each requested entity at business_at and known_at. Both intervals are [start,end); null ends are open. Normalize offset timestamps. Return results in query input order: {id,value}, with null for no match. More than one eligible version returns {id,error:"overlap"} rather than choosing arbitrarily.

The supplied rows represent already expanded system-history versions. You are implementing retrieval, not a production correction-writing engine. Original knowledge and current restatement must coexist.

## Hint

Apply both time constraints in SQL. A valid-time-only SCD2 lookup cannot answer what was known before correction.

## Deliverables and review

Two report snapshots and an overlap detector with exact-boundary evidence.

Keep the implementation, passing output, one failing counterexample, and a short note explaining the financial or operational consequence. Check the input contract rather than silently extending it. Synthetic fixtures do not establish production-scale or regulatory guarantees.
